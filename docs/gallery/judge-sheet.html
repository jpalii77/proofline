An agent that researches a small business, then re‑checks every claim with code before a seller repeats it.

People who sell web services to small businesses research them first, more and more with AI. The agents repeat stale facts with confidence: "your site is down" when it loads, a previous owner's phone, a QR-menu page taken for the shop's website. One false sentence loses the call. Proofline's rule: the model may propose, only evidence may decide.

How a run works

1. Search

Tavily finds the business by name and city. The model may take a domain or phone only from these results.

2. Propose

Nemotron 3 Super picks who the business is and proposes claims from a fixed catalog, with reasons.

3. Prove

Code re-runs a check for every claim (DNS, HTTP, TLS, map, search). A claim that fails is dropped, in plain sight.

4. Explain

Nemotron 3 Nano writes one plain sentence per proven claim; a sentence that adds a number is rejected.

RoleModelWhat code does with the answer

Every call sends a strict JSON Schema whose enums come from the run itself. A model calls panel shows each call's model, latency, tokens, cost and outcome.

Try it in 30 seconds

  • Open the demo and click the recorded example Kuzey Kafe.
  • Watch the model take a QR-menu page for the café's site, and the gate drop the three claims made against it.
  • Under any claim press Re-run proof: its checks run again, now. The interface is English and Turkish.

What it does not do

  • It cannot know an older or unrelated name: a shop selling on a site with another name is told "no website of its own".
  • A bare one-word name with no city is often "not settled" rather than guessed.
  • The hand checks were done by the team, outside the tool; a frozen final list of 12 new businesses runs once at code freeze.
